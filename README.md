# City College of Calamba Grade Computation Tool

- `frontend/` contains the static pages, JavaScript, styles, and image assets.
- `backend/public/` contains the PHP JSON APIs; `backend/config/` contains PDO and session-authentication helpers.
- `backend/database/schema.sql` creates the MySQL schema.

## Setup

1. Start Apache and MySQL in XAMPP. PHP 8.1+ is recommended; the API and development router are also compatible with the PHP 7.2 runtime included with this XAMPP installation. PHP 7.2 is end-of-life and should not be used for a public deployment. Enable PDO MySQL and mbstring.
2. Import `backend/database/schema.sql` into the MySQL/MariaDB server using phpMyAdmin or `mysql -h 127.0.0.1 -P 3307 -u root -p < backend/database/schema.sql`. Re-importing it is safe: existing grade records are preserved and account profile/calculation tables are added if missing.
3. This XAMPP setup uses MySQL port `3307`; the application defaults to `127.0.0.1:3307`, database `college_grading_system`, and the default local XAMPP `root` account. Change `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in the environment inherited by Apache if your MySQL settings differ, then restart Apache. `backend/.env.example` documents the names, but PHP does not load that file automatically. For a deployed system, create a restricted database account and configure its credentials; do not use a blank-password `root` account.
4. From the project root, create the first administrator using `C:\Users\Alejandro\Desktop\xampp_solo\php\php.exe backend\scripts\create_admin.php` (or `php backend/scripts/create_admin.php` if PHP is on `PATH`). Enter and confirm a private Admin PIN of 16–72 characters when prompted. The PIN is stored as a password hash, not as plain text. This command works only when no administrator account exists.
5. Open `http://localhost/College_System/System/frontend/` when using this XAMPP folder. Alternatively, from the project root run `php -S localhost:8000 router.php` and open `http://localhost:8000/`.

Students open `frontend/login.html` to sign in or create an account without admin approval. Signup collects a unique Username, first, middle (optional), and last name (names cannot contain numbers), numeric-only Student ID, Year Level (1st–4th Year), Department (Teacher Education, Arts and Sciences, Business and Accounting, or Computing and Informatics), and password. After successful signup, students are redirected to the login form and must sign in with their Username and password; existing accounts keep their former login ID (typically their Student ID) as their Username. The admin's Student Login Accounts table assigns student-only User IDs sequentially from 1 in account-creation order; Admin accounts do not consume those numbers, and the internal primary key remains unchanged. Students can save and view only calculations belonging to their account; administrators can review all student accounts, profile details, and saved calculations. These entries are separate from official grade records. The Student ID entered at signup is not checked against the school's student records. If signup details do not match an official grade record, the account is still created for private calculations, but official grade access is not linked. Admins use the separate `frontend/admin-login.html` page and sign in with their Admin PIN only; there is no account-type selector or Admin ID field. Admins can change the PIN from Account Settings; the server requires at least 16 characters and stores only its password hash. To link a student account to an official grade record, an admin must verify the student's identity and enable registration from Student Login Accounts; that approval is single-use and expires after 24 hours.

Private calculations are stored by account ID, and the calculations API scopes student reads and deletes to the signed-in account. For each Prelim, Midterm, and Final term, users may enter a direct grade or compute it from Auxiliary, Minor Activity, and Major Activity scores; category averages are weighted 20%, 40%, and 40%, respectively. Activity scores are saved with both student calculations and admin-managed official grade records when used. Student presence updates to Online immediately on successful login and Offline on logout. Presence heartbeats continue while the signed-in student has the system open and recent activity; after 30 seconds without a heartbeat, the admin account list marks the student Offline. Student account status refreshes every 5 seconds, while records and calculations refresh every 10 seconds. Official grade records remain admin-only unless an admin has verified and linked a student account to its saved record. Only admins can create, edit, or delete official grades and enable official-record access. Account passwords are stored as hashes; sessions use HttpOnly/SameSite cookies, and state-changing API requests require a CSRF token.

The admin Student Login Accounts section includes a searchable student directory with All, Online, and Offline filters. Selecting a student shows their account profile, linked official grade summary, and private calculation count; account statuses continue to refresh every 5 seconds while the dashboard is open.

All users who open the same hosted site use the same MySQL database. Concurrent inserts are handled by InnoDB, and official student IDs are unique. The grade API is `/backend/public/api/grades.php`; private calculations are `/backend/public/api/calculations.php`; login/session is `/backend/public/api/auth.php`; admin student-account management is `/backend/public/api/accounts.php`; and student presence heartbeats are `/backend/public/api/presence.php`. Opening the frontend using `file://` will not work.

Use HTTPS when hosting outside a trusted local network. The application has simple role-based authorization but no login rate limiting yet; protect the server and database.

Final grade weights remain 30% prelim, 30% midterm, and 40% final. When users choose activity computation, each category average is based on all scores added for that category, with each score between 0 and 100. Equivalent bands and passing mark preserve the original rules. Student IDs are unique; remove that unique index if records need to be repeated across courses or terms.
